PROJECT 01 / INTEGRATION ENGINEERING

Moving data with resilience, checkpoints and observability.

A Java multi-module portfolio toolkit exploring how external REST data can be ingested into Kafka and delivered to relational databases with operational controls and a local demonstration stack.

01 / SYSTEM OVERVIEW

A practical integration pipeline.

The toolkit pairs a paginated REST source connector with a JDBC sink. The source tracks incremental progress using stable numeric IDs; Kafka provides the event transport, while the sink writes records to a relational database. Supporting infrastructure makes the flow observable and testable locally.

02 / ENGINEERING HIGHLIGHTS

What the system demonstrates.

01

Incremental ingestion

Tracks progress using a configured stable, unique, monotonically ascending numeric ID. It is not a general-purpose opaque cursor or next-link implementation.

02

Retry and backoff

Demonstrates bounded retry handling, optional bearer authentication and Retry-After-aware backoff for transient REST failures.

03

Database delivery

Shows batching, transactions and database-specific upsert paths for supported relational targets.

04

Failure visibility

Includes dead-letter reporting integration and a local observability stack with Prometheus and Grafana.

05

End-to-end exercises

The smoke workflow exercises ingestion, offsets after restart, rebalance, DLQ behavior and database outage/recovery scenarios.

06

Reproducible environment

Docker Compose brings up the local Kafka Connect and database dependencies for repeatable exploration.

04 / SCOPE & LIMITATIONS

What this project does—and doesn't claim.

This is an actively developed engineering demonstration. The supported API contract and database behavior are intentionally bounded and documented in the repository.

  • Incremental source assumes stable, unique, monotonically ascending numeric IDs.
  • Opaque cursors, next-link tokens and out-of-order IDs are outside the current source checkpoint model.
  • Local Compose configuration is for development; secure production deployment needs TLS/SASL, managed secrets, replication and operational hardening.
  • A successful local smoke test does not establish exactly-once delivery across the full external API → Kafka → database pipeline.

For implementation details, setup instructions, tests and current limitations, see the repository documentation.
